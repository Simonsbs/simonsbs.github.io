Investigate a failed delivery

Integration Lab is a working demonstration of webhook failure and recovery. Its orders are synthetic, while signatures, HTTP requests and database writes are real.

Inspect the failure history

Run outage scenario sends four requests to an unavailable receiver. The virtual retry clock advances explicitly. The delivery becomes a dead letter, with every failed attempt still visible.

Restore service and replay

Set the receiver to Healthy, choose Replay and repair sender, then send the next attempt. The receiver records one order effect. The earlier failure history remains available.

Check duplicate safety

Queue a duplicate and send it. The receiver returns its stored response without applying the order again. Compare the delivery history with the order ledger.

Recover an ambiguous outcome

A harder case loses the response after committing. The receipt and order update are real; the failure response is injected. Retrying still leaves one order effect.

Inspect the design

The public service uses a Worker and D1. A local ASP.NET Core implementation shares its HTTP contract. The architecture board explains the receipt, retry and audit boundaries.

Understand the demonstration's limits

This is a bounded synthetic demonstration. The browser sends deliveries and controls virtual retry time. Recorded validation and source code let you inspect the behaviour and its limits.

04 / ENGINEERING JUDGEMENT

Why it works this way.

Commit the outcome together

Receipt, order effect, delivery status and audit transition commit in one optimistic SQL update. A concurrent loser reloads and recomputes.

Keep retries inspectable

Backoff, Retry-After handling and replay are explicit state transitions. Operators can see why an event is due, rejected or in dead letters.

Use a fixed receiver

The browser posts a reserved signed envelope to one controlled receiver endpoint. The session signing secret is not returned to the browser.

Scope of this project

Events, orders and failure modes are synthetic. Outages and lost responses are intentional fault injection.

The sender runs in the browser and uses explicit virtual retry time. Deliveries do not continue after the tab closes.

The demo does not claim production throughput, an uptime guarantee or distributed exactly-once delivery.
