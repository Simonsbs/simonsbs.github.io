THE PROJECT BRIEF

What should this help someone do?

Help a quality team explain which process readings are trustworthy and trace every reviewed change back to its source.

Runtime
React + TypeScript; Node SQLite / public Worker D1
Demo mode
Synthetic batches with server-enforced demo roles
01 / FUNCTION & ABILITIES

Every corrected reading keeps its original story.

01

Reconcile the ingestion

Retain raw records and reconcile usable, quarantined, duplicate and missing expected measurements.

02

Investigate known defects

Check completeness, exact and conflicting duplicates, types, units, ranges, timestamps, equipment and sampling-plan membership.

03

Review a bounded correction

Operators propose permitted field changes. Reviewer decisions check versions and findings before applying a curated overlay.

04

Follow the evidence

Inspect original/current fields, source pointers, resolved finding history, a hash-linked audit and a verifiable six-file evidence ZIP.

04 / ENGINEERING JUDGEMENT

Why it works this way.

Retain the original

Corrections update a versioned overlay. Canonical source hashes, row ordinals and the original reading remain available for investigation.

Protect concurrent reviews

A mutation token and optimistic revision guard the SQL transaction. Approval also checks the proposed measurement version.

Verify before export

Export verification checks source hashes, reconciliation, audit links and proposal/decision history before producing the evidence files.

05 / INSPECT THE EVIDENCE

Tested behaviour.
Explicit limits.

  • 40 unit tests and the same 24 HTTP scenarios on local SQLite, Worker/D1 and both public origins are recorded.

  • Local restart and public redeployment checks preserve source records, reviewed overlays, finding history and access.

  • Published browser validation includes actual downloads, independent verification, re-import and mobile layout.

Read the recorded validation

Scope of this project

All batches, readings, specifications and source-owner statements are synthetic.

One visitor can switch demo roles. This exercises server permissions, not separate verified people or independent two-person control.

The hash chain is not a digital signature. The demonstrator makes no product-release, regulatory-approval or pharmaceutical-system validation claim.
