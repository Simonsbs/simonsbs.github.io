04 / ENGINEERING JUDGEMENT

Why it works this way.

Separate data from authority

Partner error text is displayed as untrusted evidence. A fixed template uses allowlisted identifiers and codes; retrieved text cannot grant permissions.

Bind approval to the exact action

The immutable proposal binds payload hash, workspace, actor, resource, source version and expiry. Execution revalidates every binding.

Commit once, replay safely

One optimistic SQL update consumes the approval, creates the task, advances the order version and appends its audit. Replay reads the existing task.

05 / INSPECT THE EVIDENCE

Tested behaviour.
Explicit limits.

  • 40 unit tests and 34 HTTP scenarios per local/public target exercise audience, scope, malformed input, rejection, tampering, staleness and concurrent execution.

  • 20 local and 14 public browser checks include actual download, independent extraction, evidence re-import and mobile layout.

  • Local restart and public redeployment checks retain the original capability, task, proposals and complete audit state.

Read the recorded validation

Scope of this project

All operational records are synthetic. The guided runner is deterministic and does not call a language model.

One visitor owns the demo capabilities and can switch roles. Verified separate identity and two-person approval are not claimed.

Manual audience-bound bearer capabilities are used. The project does not implement an OAuth authorization server or automatic ChatGPT plugin installation.
